### 15. Orphan session branches — clean up, then prevent

Today produced two: `claude/magical-knuth-khwjye` (09:45 open) and
`claude/confident-ritchie-k7cef8` (12:00 midday). The pre-close, close and
wrap firings will produce up to three more unless their prompts carry the
explicit push line. At four to six firings a day this accumulates fast, and
every one of them is a branch that looks like it might hold work nobody has
merged.

**They are safe to delete once merged, and only then.** A merged commit is
reachable from the working branch's history permanently; the branch ref is
just a name pointing at it. Deleting the ref loses the name, not the content.

Verify before deleting, per branch:

```
git fetch --all --prune
git merge-base --is-ancestor origin/<branch> origin/claude/trading-agent-robinhood-cb9xo7 \
  && echo "MERGED — safe to delete" || echo "NOT MERGED — merge it first"
git push origin --delete <branch>
```

Do not delete any branch that fails that check, and do not delete in bulk by
pattern — a session-derived name is indistinguishable from a branch a human
made, and the check is per-branch for that reason.

**Not done today.** The two existing branches are merged and verified, but
deleting remote branches is a human's call and the cleanup should happen once,
at EOD, after the last firing has landed — not piecemeal while more are still
being created.

**To decide at EOD, with item 14:** setting an `outcome_branch` on the
Routines stops orphans being created at all, which is better than cleaning
them up afterwards. The push line in the prompt is today's mitigation, not
the fix.

### 16. `cancel_unfilled_entries()` at the close runs too late — NEW

The pre-close session cancelled the resting entry itself rather than leaving

That is right, and it means the control is correctly *scoped* and wrongly

(15:30) rather than the close (16:05), or make it a rule that any unfilled
same-day entry is cancelled before the auction. Either way this is a code
change with a test, not a prompt instruction.
